# v0.2.5 install-to-desktop investigation

The Pad's original automatic fallback is **not reproduced or diagnosed**.
Its screenshots show cleanup and subsequent Weston startup, but lack the launch
stream and readiness-gate start timestamp. The roughly six seconds shown are
cleanup time, not evidence that the 30-second gate ran for six seconds. A missing
machine after cleanup does not prove nspawn never ran.

Before implementation, unmodified `d5476ce` was installed and launched in a
Debian 13 arm64 system VM (QEMU TCG, kernel 6.12.111), using the official Arch
Linux ARM rootfs, real systemd-nspawn, seatd and virtio-gpu. Virtual-1 was forced
off and Virtual-2 on through DRM sysfs. Weston confirmed llvmpipe and no GBM
modifier support. This exercises a real second DRM output, but does not emulate
Android/crosvm's connector negotiation, lifecycle, input or display transport.

The baseline reached Hyprland IPC with Virtual-2 at 1024×768. Its Omarchy shell
then aborted: D-Bus reported zero-length machine IDs. The nonboot rootfs had
never initialized `/etc/machine-id`; `/var/lib/dbus/machine-id` was an absolute
symlink to that empty file. Reading that link through a host filesystem prefix
would misleadingly read the host ID. The fix initializes the container's own
persistent identity before nspawn and preserves valid IDs on every rerun.
Confidence in this VM diagnosis is high; attribution to the Pad remains unknown.

After repairing identity, the real shell exposed a second defect: Qt 6.12's new
`QtQuick.Color` shadowed Omarchy 4.0.4's color singleton. An installed-package
probe showed unqualified Color resolving to QQuickColor with no bar property,
while explicit qualification exposed the correct theme roles. Patch 0004
qualifies shipped consumers without renaming Omarchy's public singleton. See
[Qt's type documentation](https://doc.qt.io/qt-6.12/qml-qtquick-color.html) and
[the upstream report](https://github.com/omacom/omarchy/issues/14548).
Third-party plugins using unqualified Color need the same qualification.

Aquamarine EGL device matching / initMgpu errors appeared even with working
primary scanout. No speculative GPU or renderer patch is included. Existing
software-rendering and no-modifier defaults remain in effect.

Bootstrap independently reproduced the old full-SHA `git clone --branch` failure.
The Pad's Gitee archive 404 did not reproduce from this host (HTTP 200 here);
the fix removes archive requests entirely, installs missing Git through apt,
and clones a branch/tag (main for a SHA) before verified checkout. CN selects
Gitee; branch/tag/SHA tests assert no GitHub fetch and no archive request.
The operator synchronizes Gitee main and the tag after each origin release.

## Pad selftest and persistent diagnostics

Update from README's main-ref command using the same user/rootfs settings.
For v0.2.6 and later, run `~/.local/bin/arch-selftest` directly from Linux Terminal's
text tab; it stops and restores both display units (see [current validation](v0.2.6-validation.md)).
For historical v0.2.5, stop `weston.socket` and `weston.service` from an independent
text terminal or SSH connection before running the test,
then run `~/.local/bin/arch-selftest`. It refuses an existing container or busy
seat, runs once in the foreground, captures diagnostics before bounded cleanup,
and prints one private log path. It never falls back to Weston. Exit 0 means
output IPC became ready and cleanup succeeded; inspect the screen separately.

Every ordinary Arch launch also records stdout/stderr and stage timestamps in
`~/.local/state/omarchy-alarm/arch-session-*.log`. `arch-diag` creates an additional
private report, including previous attempts, raw monitor data, journals, shell
logs and real Hyprland runtime logs. `arch-output --logs` works after teardown
when runtime files remain. An explicit missing-log marker distinguishes absence
from silently looking in the wrong directory. Files are mode 0600, directory
0700. Session logs are capped at 8 MiB; overflow keeps the newest 4 MiB before
appending more output. Session and diagnostic logs each retain ten files.
Truncation is marked. Copy important evidence before
repeated retries; recovery instructions are in troubleshooting.md. Raw logs can include window titles, workspace names and device identifiers.

To return to Debian, run `hypr-switch debian`, then fully close/reopen Android
Linux Terminal. Switching only records the choice; `--now` also remains deferred.
