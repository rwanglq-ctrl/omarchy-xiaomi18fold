# v0.2.6 validation

## Diagnosis and scope

The connector changes between boots. The Pad screenshots show Virtual-1 connected
on the later boot; the earlier report showed Virtual-2. The connector argument in
v0.2.5 came from the sysfs loop in `host/bin/arch-output`, not a fixed default.
It was passed to the inner shell as a sorting preference, not to hyprctl as a
monitor selector. The real gate accepts any usable non-headless monitor.

A Debian 13 arm64 system VM reproduced the startup failure after adding an active
`weston.socket` at `/run/user/1000/wayland-0`. Hyprland printed its welcome message,
created `.socket2.sock`, then stopped before creating `.socket.sock` or its lock
file. The runtime mount and UID were correct; the old `nsenter -a` probe could
already query monitors in the earlier working run. Explicit root/cwd entry is
additional robustness, not the demonstrated cause.

The VM backtrace shows the main thread blocked in
`Aquamarine::CWaylandBackend::start` → `wl_display_roundtrip_queue` → `ppoll`.
`ss` shows a queued connection to the systemd-owned wayland-0 listener, with no
Wayland server answering it. Aquamarine starts its optional Wayland backend even
with DRM available. With WAYLAND_DISPLAY unset, libwayland selects wayland-0.
Hyprland is replacing the service that would answer that connection: startup
cannot finish, and the readiness probe has no command socket to connect to.

Sources: [Aquamarine 0.15.1 backend startup](https://github.com/hyprwm/aquamarine/blob/v0.15.1/src/backend/Backend.cpp)
and [Wayland connection and roundtrip](https://github.com/hyprwm/aquamarine/blob/v0.15.1/src/backend/Wayland.cpp).
The VM uses Hyprland 0.56.2, Aquamarine 0.15.1, Mesa 26.2.4 and Debian kernel
6.12.111. The Pad screenshot reports Android kernel 6.12.93; physical Pad
confirmation remains outstanding.

The first fix used `WAYLAND_DISPLAY=/dev/null`. Gold alignment now clears
`WAYLAND_DISPLAY` and `WAYLAND_SOCKET`, and masks any existing host wayland-0
with a read-only `/dev/null` bind **inside the container mount namespace**.
The host socket remains intact for fallback. This matches the reference's lack
of an available parent display (its old socket is `.weston-socket-unused`).
The arm64 VM verifies this with weston.socket active, usable monitor IPC, and
successful selftest followed by restoration of both units.

The screenshots also prove a separate fallback bug: Weston reported “invalid
socket provided from systemd.” Session logging overwrote activation FD 3.
The wrapper now preserves that socket on FD 7 and restores FD 3 before Weston.
The `(EE) could not connect to wayland server` line appears during cleanup;
it is consistent with a departing Wayland client and does not locate the initial
failure. The user manager's cgroup kill EPERM does not establish a DRM fault:
owned nspawn cleanup uses privileged machinectl, then verifies registration is
gone before allowing fallback.

## Self-test and regression coverage

From Linux Terminal's text tab or an independent SSH session, run:

```bash
~/.local/bin/arch-selftest
```

It closes graphical applications, stops weston.socket before weston.service,
waits boundedly for the session lock and DRM seat, runs the real gate, collects
private evidence before teardown, and restarts both display units on success,
failure or handled signals. Exit 0 proves usable monitor IPC and cleanup, not
visible pixels on the physical Pad. SIGKILL and power loss cannot run traps.

A stale recorded PID is cleared only after acquiring the kernel flock. The lock
inode is never deleted. A live holder is reported with PID and command; unrelated
owners are not killed. The logger and container launcher do not inherit the
session lock. Weston retains ownership while it holds the display.

Behavioral tests exercise the real rendered gate and selftest scripts with
external command mocks and real UNIX sockets: Virtual-2 then Virtual-1 on
successive boots, socket/lock discovery when instances fails or hangs, absent
command sockets, stale instances, bounded probes, socket-first stopping,
restoration after failures and signals, dead metadata and live lock holders,
activation FD preservation, namespace-entry failure with surviving host log capture, and parent-display
connection rejection. Earlier
VM coverage lacked the socket-activation fixture; earlier unit coverage mocked
arch-output itself, hiding its namespace/socket behavior.
